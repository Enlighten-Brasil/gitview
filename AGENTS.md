# AGENTS.md — gitview

Dashboard do gestor de dev (open-source, MIT) para acompanhar commits, PRs e releases do time nos repositórios da org do GitHub. Qualquer pessoa que clona roda `pnpm install && pnpm dev` — a config de máquina vive no `.env` (criado do `.env.example`) e o cadastro do time no `team.local.json` (gitignored); nada pessoal é versionado. Ferramenta **read-only** sobre os dados — nunca escreve nos repos analisados.

## Arquitetura

```
git log  →  data/gitview.db (node:sqlite, incremental)  →  public/data/stats.json + commits.json
API GraphQL do GitHub (token .env/gh)  →  public/data/github.json (PRs + reviews)
clones (for-each-ref + git log --no-merges)  →  public/data/branches.json (inventário de branches: status/ahead/behind/autores)
git tag + API REST do GitHub  →  public/data/releases.json (tags + notas de release)
team.local.json + stats/github  →  team.json (devs + times + candidatos)
public/data/*.json     →  check-data.ts (valida shape + invariantes no fim da coleta; erro = coleta falha)
```

O frontend (Vue 3 + TS + Vite + ECharts + Nuxt UI v4 / Tailwind v4) é **100% estático**: só lê os JSONs de `public/data/`, nada é recalculado do git no navegador. `public/data/*` e `data/` são gitignored — sempre regenerados pelos coletores.

### Coletores (`scripts/`)

| script | saída | fonte |
|---|---|---|
| `collect.ts` | `stats.json` (agregados weekly/monthly/heatmap por mês/monthlyTypes/perAuthor/perRepo/repoUrls) + `commits.json` (100 últimos/autor) | `git log --all --no-renames --no-merges --numstat --since=<watermark-7d>` → SQLite (`INSERT OR IGNORE`, incremental; `--full` = re-scan; `--reaggregate` = sem git, só re-aplica aliases + re-exporta). **Merges ficam fora de TODAS as métricas** (decisão issue #7: 17,6% dos commits eram `Merge …` com +0−0, inflando commits/dia, ritmo e streaks; a "produção" do merge já está no PR). São removidos no `git log` por topologia (`--no-merges`), não por assunto — um commit single-parent com assunto "Merge" (squash/pull regravado) entra. Retroativo: histórico antigo no banco ainda tem merges, precisa `pnpm clean && pnpm collect`. Datas gravadas em **UTC ISO com milis** (migração automática na 1ª execução; o %aI do git emite o offset do autor, que quebrava comparação lexicográfica). **Fuso canônico**: todos os buckets de tempo (mês/dia/semana ISO/fim de semana/madrugada/heatmap) são calculados em `GITVIEW_TIMEZONE` (default `America/Sao_Paulo`) via `Intl`, nunca no relógio da máquina — o mesmo banco dá agregados byte-idênticos em qualquer TZ (issue #8; o `isoWeekKey` antes usava UTC e os demais buckets o fuso local — inconsistência corrigida; streaks usam aritmética calendária pura). **Escopo de ref** (#118/#119): o banco grava por commit `scope` (`prod` = alcançável da ref de produção · `integration` = alcançável das refs de integração e não de prod · `branch` = demais) + `ref_hint` (primeiro ref alcançável, melhor esforço — branch longeva engole a atribuição; NULL se alcançável só por tag). Classificação a cada collect com git (`lib/scope.ts`: sets de `git rev-list` + walk escoteado `log --branches --not … --source`; UPDATE só nas linhas mudadas — branch mergeada vira prod sem `--full`; `--reaggregate` pula e, havendo NULL, avisa sem emitir contagens). Refs configuráveis: `GITVIEW_PRODUCTION_REF`/`GITVIEW_INTEGRATION_REFS` (seam `lib/refs.ts`: explícito global com fallback por repo — origin/HEAD → HEAD → main → master). Nos JSONs, encoding **omit-prod**: `scope` ausente = prod (viaja só `integration`/`branch`); `totals.prodCommits`/`progressCommits` (progress = integration+branch) + ambos por linha de `perRepo`; linhas scope NULL ficam fora dos buckets/totals com aviso. Linhas de lockfiles/gerados são filtradas **no parse do numstat** (nunca via pathspec — isso removeria commits inteiros); lista em `DEFAULT_EXCLUDE_PATHS` + `GITVIEW_EXCLUDE_PATHS` |
| `collect-github.ts` | `github.json` (PRs OPEN todos + MERGED últimos 400d, filtrados por `mergedAt` na janela, reviews inline com paginação por cursor além de 100, mapa login→dev) | API GraphQL do GitHub via `fetch` (`ghGraphql` em lib/github.ts, token do `.env`/`gh auth token`) — incremental: refetch só de PRs atualizados desde a última coleta, merge com o JSON anterior; `--full` ignora o cache |
| `collect-branches.ts` | `branches.json` (inventário de refs/heads por repo: productionRef/integrationRefs + branches com tip, lastActivity, ahead/behind vs prod e vs a 1ª integ SEM merges, autores à frente com e-mail cru (%ae), linhas +/−, status) | `git for-each-ref refs/heads` + `git log --no-merges` nos clones (pool de 4, spawn async; seam `lib/refs.ts` em pré-passo sync). Status = union fechada `production|integration|feature|bot|pousada` (`BOT_BRANCH_RE` dependabot/renovate + `GITVIEW_BOT_BRANCHES`; pousada = ahead 0 e ≥ `GITVIEW_BRANCH_STALE_DAYS` dias sem atividade, default 30). E-mail cru de propósito: fato puramente git — o frontend mapeia e-mail→dev via team.json. Só na coleta FULL (a light não faz fetch — o inventário ficaria idêntico ao último full, só custo) |
| `collect-releases.ts` | `releases.json` (tags com data, commits entre tags, não liberados, notas do GitHub) | `git tag` + API REST do GitHub (`ghApiAll`; sem token → só tags; paginado até 1000 releases/repo, falha vira warning). Contagem de commits por release compara **timestamps** (nunca texto) |
| `collect-team.ts` | `team.json` (devs: perfil título/descrição + e-mails + logins + times; times; candidatos sem mapeamento) | `team.local.json` (`devProfiles`/`teams`/bots) + stats/github.json já gerados. Logins dedup por case (grafia da API prevalece) |
| `check-data.ts` | — (só valida; exit 1 em erro) | lê os 6 JSONs de `public/data/`; asserts de estrutura + invariantes (ΣperAuthor/ΣperRepo/Σmonthly == totals.commits, totals.prodCommits+progressCommits == totals.commits, Σmonthly sem scope == prodCommits e com scope == progressCommits, `scope` presente ∈ {integration,branch} — union fechada, prod não viaja no JSON, datas UTC uniformes, commits.json em ordem desc real + hash 7-hex, PR MERGED com mergedAt + sem duplicata repo#number, releases com unreleased+Σtags == commits do repo, login sem duplicata por case, branches com exatamente 1 `production` por repo (nome == productionRef), nomes únicos, tip 7-40 hex, `status` ∈ union fechada, repo ∈ stats#repos, authorsAhead com '@') + **avisos não bloqueantes** (membro de time que também é candidato, dev sem alias, lastCommit no futuro, commit com assunto de merge e diff zero na amostra de commits.json, repo com commits e nenhum em produção — ref suspeita, lastActivity no futuro, repo sem ref de integração) |

Os 4 coletores de dados processam os repos em paralelo (pool de 4). Logins do GitHub → nomes canônicos via `devProfiles` (mapeamento **explícito**, não fuzzy). Bots: `DEFAULT_GITHUB_BOTS` (lib/team.ts) + `githubBots`/`bots` do `team.local.json`. Aliases efetivos = `devProfiles[nome].emails` + `.githubLogins` — merge em `scripts/lib/team.ts` (`resolveAliases`), usado por collect.ts e collect-github.ts.

Config dos coletores (`scripts/lib/config.ts`): merge do `.env` (gitignored, criado do `.env.example` na 1ª execução; chaves `GITVIEW_*` — token, client id, org, `reposRoot`, defaultRepos, exclude, excludePaths, porta, timezone, productionRef, integrationRefs, branchStaleDays, botBranches) + `team.local.json` (devProfiles/teams/bots). Precedência: shell > `.env` > default. `saveConfig()` roteia cada campo para o lugar certo (`.env` linha-a-linha preservando comentários, valores `'single-quoted'`; `team.local.json` JSON). O arquivo é relido **a cada chamada** (`envDir: false` no Vite — o dev server não carrega nem vigia `.env`, senão o setup mataria o SSE próprio ao gravar o token). `reposRoot` resolve: shell → `.env` → `data/repos`; se nada existir, erro com instruções (ver README). Migração única (`scripts/lib/legacy.ts`, disparada por `loadConfig`): `config.json`/`config.local.json` antigos viram `.env` + `team.local.json` e o local é renomeado `.migrated`.

O setup (`scripts/setup.ts` CLI e a UI) usa `GITVIEW_GITHUB_ORG`/`GITVIEW_DEFAULT_REPOS` do `.env`: lista os repos via API REST, clona os escolhidos em `data/repos/` (**bare**, gitignored) e grava `GITVIEW_REPOS_ROOT=data/repos` no `.env`. Clones gerenciados recebem `git fetch --all --prune --tags` no início do `collect.ts` — o token é injetado por `GIT_CONFIG_COUNT/KEY/VALUE` (só no processo do comando; nada de token no argv nem no config do clone; `scrubPersistedToken` limpa headers gravados por versões antigas) — e `denyPush` (`remote.origin.pushurl=no-push`), trava read-only no nível do git, idempotente, aplicada no clone e a cada coleta. Discovery compartilhada em `scripts/lib/repos.ts` (aceita checkout normal e bare; `isManagedRepo` identifica os clones do setup).

Limpeza: `scripts/lib/clean.ts` (`cleanLocalData`) apaga banco + `public/data/*.json` (tudo regenerável; clones só com flag — **nunca** apaga `.env`/`team.local.json`, que não são regeneráveis) — usada pelo `pnpm clean` (`scripts/clean.ts`) e pelo `/__collect?clean=1`.

`scripts/lib/github.ts` centraliza o acesso HTTP à API do GitHub (coletores **e** setup): `getToken()` (`GITVIEW_GITHUB_TOKEN` do `.env`/shell → `gh auth token`; o **gh CLI é ponte opcional**, ninguém precisa dele instalado pra coletar), REST (`ghApi`/`ghApiAll` — path com `/` inicial), `ghGraphql`, `currentUser`, `listOrgs`, `listOrgMembers`/`listOrgTeams`, `listOrgRepos`/`listUserRepos` e o **device flow** (`deviceStart`/`devicePoll`, sem client secret). O device flow aceita **GitHub App** (client_id `Iv…` — sem scope, o token herda as permissões do app; recomendado: *Contents read-only* = token fisicamente read-only) e **OAuth App** (`Ov…`/hex — scope `repo read:org`, read+write; mitigado pelo `denyPush`). O `cloneBare`/`fetchRepo` autenticam via `gitAuthEnv` (Basic `x-access-token` serve pra PAT/OAuth/GitHub App), sem gravar segredo em disco.

### Rotas (vue-router 5 file-based)

`src/pages/` gera as rotas (plugin `vue-router/vite` no vite.config, **antes** do `vue()`). Nomes de rota = caminho de arquivo sem os grupos `(app)/(dashboard)` (`getRouteName` custom; `/devs/[name]` etc.; separadores `.` do nome plano viram `/` — `teams.[name].vue` → `/teams/[name]`; dots dentro de `[...]` são preservados) — o mapa tipado `src/route-map.d.ts` é **gerado e commitado** (typecheck sem dev run). Cuidado: arquivo `x.vue` + pasta `x/` na MESMA pasta aninha os filhos dentro de `x.vue` (exige RouterView) — use o nome com ponto ou `_parent.vue`. Layouts aninhados via `_parent.vue`:

```
pages/
├── (app)/_parent.vue            shell: rail + navbar + coleta · meta.requiresData
│   ├── (dashboard)/_parent.vue  faixa de abas (links p/ rotas) · section/filtros herdados
│   │   ├── index.vue  /          devs.vue  /devs   health.vue  /health
│   ├── devs/[name].vue           alias /dev/:name
│   ├── repos/index.vue  /repos   repos/[name].vue  /repos/:name (alias /repo/:name)
│   │   └── índice inclui #releases (a página /releases virou seção aqui; redirect legado no guard)
│   ├── prs.vue · teams.vue (/teams, alias /team) · teams.[name].vue (/teams/:name — dashboard do time; ponto no nome = não aninha sob teams.vue)
│   └── settings/  (index · repos · account)     requiresServer
├── setup/  (_parent onboarding · index · github · repos · collect · team)
└── [...path].vue                 404
```

- **`route.meta` é o contrato** (tipado em `src/router/meta.ts`): `requiresData` (sem dados → guard manda `/setup`), `onboarding` (com dados → `/settings`; sem auth → passo 1), `requiresServer` (build estático → fora), `setupStep` (2/3 exigem auth; 3 exige seleção no sessionStorage; 4 exige dados coletados — é a única rota `/setup/*` que sobrevive ao ter dados), `section` (rail/painel contextual), `filters` (`full|team|period|period-bots|none` — o que a sidebar E a URL carregam; `team` = período+repos, os devs são travados pela página), `title` (navbar). `definePage()` não aceita guards → tudo vive em `src/router/guards.ts`.
- Guard global (`beforeEach`): 0) legado `/?tab=prs|repos|team|health` → rotas novas preservando query; 0b) legado `/releases` → `/repos#releases`; 1) boot único (`ensureBoot` = loadStats 1×; splash no App.vue enquanto `router.isReady`); 2–5) regras do meta acima. `resetBoot()` é chamado depois de coletar no wizard / apagar dados / limpar (senão a navegação seguinte herdaria "sem dados" do boot antigo).
- HMR de rotas: `handleHotUpdate(router)` em `src/router/index.ts`. Scroll: `src/router/scroll.ts` (afterEach — o container é o body do painel, não a janela; âncoras com retry porque ECharts atrasa o layout). `base: '/'` + `createWebHistory` — deep links exigem SPA fallback no servidor que servir o dist.

### Setup pela UI (dev only)

`scripts/setup-plugin.ts` é um plugin Vite (`apply: 'serve'`) que alimenta o **wizard** `pages/setup/*` (rota `/setup/github|repos|collect|team`) e a tela de **Configurações** `pages/settings/*` (`/settings`, `/settings/repos`, `/settings/account`) — os componentes compartilhados vivem em `src/components/setup/` (`GithubConnect.vue` device flow+PAT+gh / `RepoPicker.vue` escolha de repos / `RunLog.vue` progresso SSE). Sem dados: wizard de 3 passos + **passo 4 opcional** (`/setup/team`, mapeamento de identidades); com dados: `/setup/*` cai em `/settings` (guard — exceto o passo 4). Ao concluir a coleta no passo 3, "abrir dashboard" só passa pelo passo 4 se `team.json#candidates.length > 0` (sem candidatos, vai direto ao dashboard). Gerenciar repos abre a lista pré-selecionada com os repos atuais (badge "atual"); desmarcar um atual mostra alerta de remoção e o apply apaga o clone do disco. A seleção do passo 2 sobrevive a F5 via `src/wizard.ts` (sessionStorage). Endpoints (todos dev only):

- `GET /__setup/status` — auth (user + fonte do token), `oauthConfigured`, `reposRoot`, repos gerenciados, `hasData`. Sondado a cada 5s enquanto a tela de auth está aberta (detecta `gh auth login` e troca de conta — volta às configurações quando o login muda).
- `GET /__auth/device` — inicia o device flow (só se `GITVIEW_GITHUB_CLIENT_ID` no `.env`); `POST /__auth/device/poll` — conclui e grava o token no `.env`. **Ordem importa**: o poll é registrado ANTES no connect, que casa middleware por prefixo (`/__auth/device` engoliria `/poll`).
- `POST /__auth/token` — PAT colado na UI: valida em `GET /user` **antes** de gravar no `.env` (401 com mensagem se o token não presta); `POST /__auth/logout` — limpa a chave (`GITVIEW_GITHUB_TOKEN=`; se o gh estiver logado ele reassume a ponte, e o status reflete).
- `GET /__setup/orgs` — orgs do usuário + entrada `@user` (repos pessoais); `GET /__setup/repos?org=` — payload enxuto (`name`, `archived`, `pushed_at`, `private`).
- `GET /__setup/apply?org=&repos=a,b&dry=1&remove=c,d` — SSE com lock: remove os clones listados em `remove` (só gerenciados, nome sanitizado), clona os faltantes (pool de 4; exige token), grava `reposRoot` no `.env`; `?dry=1` valida sem efeitos. Remoção é sempre explícita (nunca prune por diferença de lista).
- `GET /__clean[?repos=1]` — apaga banco + JSONs sem recoletar (com `repos=1`, apaga também os clones) — mesma lib do `pnpm clean`; é o botão "apagar dados" (volta ao wizard; o `/` redireciona por causa do gate).
- `GET /__team/github` — membros + times da org (`githubOrg`) via REST (para importar). Requer token com `read:org`; falha parcial (ex.: sem permissão → times vazio) vem no campo `warnings` (a UI mostra no modal de import).
- `GET/POST /__team/config` — lê/grava `devProfiles` + `teams` no `team.local.json` (sanitização de payload em `sanitizeDevProfiles`/`sanitizeTeams`). O POST **regenera o `team.json`** em seguida (`collect-team.ts` + `check-data.ts` via `refreshTeamData`) e devolve `teamRefreshed`/`warnings` — nomes/cores/membros e `renamedFrom` valem na hora para chips, `/teams/<nome>` e dashboards; a UI recarrega o `team.json` (`loadTeam(true)`). Corpo com `skipRefresh: true` pula essa regeneração (o "salvar + recoletar" usa — a recoleta leve já regenera; follow-up #12). Aliases de identidade continuam pedindo a recoleta (mexem no `stats.json`) — por isso o botão "salvar + recoletar" existe.

### Time pela UI (rota `/teams`)

`pages/(app)/teams.vue` + `src/team.ts`: página fora do dashboard pra gerenciar **times** (nome, descrição, cor, membros) e **perfis de devs** (título, descrição, e-mails de commit, logins do GitHub extras). Persiste em `team.local.json` via `/__team/config` (só a máquina — dados de gestão não versionados). UI (0.34): cards de time (`components/team/TeamCard.vue`) com avatar de iniciais, paleta de cor em popover, membros como chips removíveis + combobox de adição (hint "já em: outro time") e **métricas agregadas** por time (devs/commits/PRs do último commit — total histórico, `metricsFor`); cards de dev (`components/team/DevCard.vue`) com avatar, badges de time coloridos, contagem de aliases (detalhe no tooltip) e link pro perfil de commits quando existe; **barra sticky de gravação** com status dirty / *desfazer* (revert ao snapshot salvo) / *salvar* / *salvar + recoletar*; skeleton enquanto o `team.json` chega; remoção de time com confirmação inline (sem `window.confirm` no card). Botão **importar do GitHub** traz times e membros da org (`/__team/github`); times importados resolvem logins→devs pelos aliases já mapeados. A seção **Sem mapeamento** lista autores do git e logins do GitHub vistos nos dados sem alias (do `team.json#candidates`) e associa a um dev — a unificação vale na coleta seguinte (`resolveAliases`). Candidatos com e-mail corporativo recebem **sugestão de associação** (tokens do local-part × tokens do nome do dev, ≥2 tokens casando; pré-seleciona o dropdown com badge "sugestão" — a confirmação continua manual). "Salvar + recoletar" roda a **recoleta leve** (`startCollect(false, false, true)` → `/__collect?light=1`: `collect --reaggregate` + github incremental + team + check-data, sem re-escanear o git) — só se o salvar der certo. (Remover alias não reverte nomes já gravados no banco — isso só a limpeza completa refaz.) No build estático a página é somente leitura (endpoints dev only) — devs **e times** são renderizados do `team.json` (times entram no editor via seed no `onMounted`, já que `/__team/config` não existe; cards ficam `disabled`). Bot de perfil não entra em `devNames` (não é alvo de associação) e não recebe botão de edição. **Dashboard por time** (issue #9): cada card tem link "abrir dashboard" → `/teams/<nome>` (`teams.[name].vue`; o `.` evita aninhar sob `teams.vue`, que não tem RouterView). A página trava `filters.authors` nos membros (watch re-aplica até depois do `sanitize`), escopo `filters: 'team'`; rename na UI grava o nome anterior em `teams[].renamedFrom` (`team.local.json` → `team.json`; comparação por `cid`+`savedName`, não por índice) e `/teams/<nome-antigo>` faz `replace` pro canônico preservando a query; botão "ver como filtro livre" → `/?devs=<membros>`.

Gate de primeira execução: o guard global exige `requiresData` — sem `stats.json`, **toda** rota de dados cai no wizard (`/setup`), que renderiza sem rail/navbar; splash no `App.vue` cobre o boot (loadStats 1× aguardado pelo guard). A seção Config (⚙) da rail só aparece em dev. O passo 1 de auth (`/setup/github`) oferece device flow (com Client ID no `.env`), colar PAT ou a ponte do `gh auth login` (detectado via sonda).

A tela **Configurações** (`/settings`, com dados) tem os cards **Refs dos repositórios** (produção/integração com hint resolvido por repo — dev only) e **Manutenção dos dados locais** com 3 ações: *recoletar tudo* (`startCollect(true)`), *limpar e recoletar* (wipe + full, `startCollect(false, true)` via `/__collect?clean=1`) e *apagar dados* (confirmação inline com checkbox de clones → `/__clean`, `stats.value = null` + `resetBoot()` + `router.replace('/setup')` — sem reload).

### Coleta pela UI (dev only)

`scripts/collect-plugin.ts` é um plugin Vite (`apply: 'serve'`) que expõe `GET /__collect` (SSE; `?full=1` = completo; `?clean=1` apaga banco + JSONs antes e implica full; **`?light=1` = recoleta leve** — `collect --reaggregate` + github incremental + team + check-data, sem git scan nem releases) rodando os passos com progresso ao vivo. O botão ↻ no navbar (`App.vue` + `src/collect.ts` — `startCollect(full, clean, light)`) só renderiza em `import.meta.env.DEV`; após o `done`, os loaders refazem o fetch com cache-bust (`loadStats/loadGithub/loadReleases/loadCommits/loadTeam` aceitam `force`). No build estático o endpoint não existe.

## Comandos

```bash
pnpm collect            # os 5 coletores em sequência + check-data no fim
pnpm collect:github     # só PRs
pnpm collect:branches   # só inventário de branches
pnpm collect:releases   # só releases
pnpm check:data         # só a validação de shape + invariantes dos JSONs
pnpm check:scrub        # gate anti-regressão do scrub de identidade (roda no CI)
pnpm lint               # eslint (@antfu/eslint-config — padrão da org; config em eslint.config.js)
pnpm typecheck          # tsc --noEmit (scripts + src; templates .vue fora)
pnpm dev                # http://localhost:5173 (Vite)
pnpm start              # alias do dev (setup/coleta só existem no dev server)
pnpm build              # dist estático
pnpm changeset          # registrar mudança
pnpm version:packages   # aplicar changesets (bumps + CHANGELOG)
```

## Convenções obrigatórias

- **Toda mudança** = changeset (`minor` feature / `patch` fix) → `pnpm version:packages` → commit único com `chore(release): X.Y.Z` no corpo. Versão atual: ver `package.json` / `CHANGELOG.md`.
- **Commits em pt-BR** (Conventional Commits), código em inglês, comentários em pt-BR.
- **Windows / PowerShell 5.1**: usar `pnpm.cmd` (o shim `pnpm.ps1` é bloqueado pela Execution Policy). **Nunca** editar arquivos UTF-8 via PowerShell (mojibake) — usar as ferramentas de edição. **Nunca** piper CLI que muta arquivos com `2>&1 | Select-Object` (pode abortar no meio).
- ESLint `@antfu/eslint-config` (`eslint.config.js`, padrão do maintainer do gitview — espelhado direto no arquivo, já que o repo é OSS): sem ponto-e-vírgula, aspas simples. `pnpm lint` é gate (zero erros).
- **Copy de feedback** (padrão unificado na 0.46): toasts (`useToast`) com título curto em inicial maiúscula ("Perfis salvos", "Imagem exportada"), descrição em minúsculas, `color` sempre explícita; toda ação com efeito emite toast de sucesso/erro (nada de ação muda). Confirmações destrutivas sempre via `useConfirm()` (UModal): título = pergunta direta ("Descartar alterações?"), `description` = consequência concreta, `confirmLabel` = a ação ("descartar", "remover time") — proibido `window.confirm`, swap inline e UModal ad hoc.
- Deleção de arquivos: `rm -- <path>` (launcher recuperável), nunca `Remove-Item`.

## Estrutura do `src/`

- `data.ts` — fachada (reexports, issue #41) dos filtros globais (`filters`), agregações filtradas (monthly/weekly/heatmap/types), totais + delta (`previousTotals`), ritmo (`pace`), burnout, off-hours por período — implementação em `filters-core.ts` / `filters.ts` / `date.ts` / `aggregations.ts` (consumidores continuam importando `@/data`).
- `github.ts` — PRs filtrados, aging, cycle time (mediana geral/por repo/tendência 6M), reviews por dev e concentração por repo, merge sem review.

## Regras dos filtros (importante pra não "corrigir" o que é intencional)

- **Vocabulário de escopo** (baked, não renomear): scope de DADOS = `prod|integration|branch` (banco; nos JSONs **omit-prod** — `scope` ausente = prod) · filtro de frontend = `filters.workScope` = `all|prod|progress` (progress = integration+branch; URL `?scope=` — chega na #128) · `FilterScope` de ROTA (`route.meta.filters` — `full|team|period|period-bots|none`) = conceito distinto (quais filtros a rota carrega), intocado.
- Filtro de período: presets (1/3/6/12/24M, Tudo) **ou** range custom `dateFrom/dateTo` (YYYY-MM-DD, prevalece sobre preset, corta **por mês inteiro** — a agregação é mensal/semanal). Delta dos cards é omitido em range custom e em "Tudo".
- **Times na sidebar** (escopo full): chips de time no FilterBar (des)marcam todos os membros de uma vez — materializam em `filters.authors` (a URL carrega os devs, não o time). Estado do chip: todos/parcial/nenhum selecionado.
- **`/teams/:name`** (escopo `team`): os devs ficam **travados** nos membros do time pela página (sidebar sem seção Devs/bots; URL só com período+repos). Sair da página mantém os membros como seleção visível no dashboard (mesma regra de contexto preservado do escopo full — nada de filtro invisível). Time renomeado: `/teams/<nome-antigo>` redireciona pro atual (histórico em `teams[].renamedFrom`, gravado pelo editor /teams).
- Janelas fixas intencionais (ignoram o período, estão rotuladas no rodapé): Ritmo (4 vs 8 semanas), OffHoursPanel no modo "8 semanas" (o modo "período" segue o filtro), Tendência de cycle time (6 meses), PRs abertos ("agora"), Ranking do time (histórico completo), Inatividade (medida até hoje, ignora todos os filtros).
- **Páginas `/devs/:name` e `/repos/:name` respeitam o filtro de período** (desde 0.27.0): cards de commits/linhas/devs, gráficos, PRs mergeados, cycle time, reviews e lista de commits ficam restritos ao período; "Tudo" = histórico completo. Ficam fora do período por decisão: dias ativos/streak/repos (rotulados `(total)`), PRs abertos ("agora") e releases (marcos). Heatmap de horários em "Tudo" cobre no máximo 24M (limite da agregação). Na sidebar, essas rotas mostram **só o seletor de período** (+ switch de bots em `/repos/:name`, que passa a valer para commits/tipos/PRs do repo).
- `/prs` e `/repos` (índice) usam o escopo `full` de filtros — visíveis na sidebar **e** na URL (decisão 0.33: escondê-los mas aplicá-los era a fonte de "filtro fantasma").
- Thresholds dos painéis de Saúde estão documentados no rodapé de cada card.
